# 编程范式与核心思想

**一句话**：编程范式就是写代码的"思维套路"，它决定了两件事——**代码怎么组织**、**控制权在谁手里**。

---

## 一.思维模型类（代码怎么写、数据怎么流）

这一类决定了你从什么角度去组织业务逻辑与数据结构。

**1. 面向对象编程（OOP）**
- **核心思想**：通过封装、继承、多态，把**数据与行为**打包成"对象/类"。
- **主流载体**：Java、TypeScript/JavaScript（class）、Python（class）、C++。
- **工程场景**：构建软件整体骨架、大型系统架构与领域模型。

```ts
class User {
  private balance = 0            // 封装：数据藏起来
  constructor(public name: string) {}
  pay(amount: number) {          // 行为跟着数据走
    if (amount > this.balance) throw new Error('余额不足')
    this.balance -= amount
  }
}
```

**2. 函数式编程（FP）**
- **核心思想**：以纯函数为核心，追求**无副作用、数据不可变、管道化变换**。
- **主流载体**：TS/JS（map/filter/reduce）、Java（Stream API）、Python（lambda）。
- **工程场景**：海量数据清洗、状态管理（如 Redux）、复杂数据映射转换。

```ts
// 不修改原数组，一路"管道"流下去
const result = users
  .filter(u => u.age >= 18)
  .map(u => u.name)
  .reduce((acc, name) => acc + name + ', ', '')
```

> **纯函数**：同样输入必得同样输出，且不碰外部状态。副作用（改全局变量、写库、打日志）越少，越好测。

**3. 面向过程编程（POP）**
- **核心思想**：按逻辑顺序一步步编写函数与控制流。
- **主流载体**：C 语言、各类 Shell / Python 自动化运维脚本。
- **工程场景**：系统底层开发、轻量级脚本任务、极简批处理。

## 二.运行与控制类（代码怎么联动、事件怎么响应）

这一类决定了控制权的传递方式以及各模块间的异步/联动机制。

**1. 声明式与命令式（Declarative & Imperative）**
- **核心思想**：命令式关注"**一步步怎么做**"，声明式关注"**直接要什么结果**"。
- **主流载体**：SQL、HTML/CSS、Vue/React 模版语法。
- **工程场景**：数据库查询、UI 界面声明与渲染。

```sql
-- 命令式：自己 for 循环、判断、累加
-- 声明式：只说"我要什么"
SELECT dept, AVG(salary) FROM emp WHERE age > 25 GROUP BY dept;
```

**2. 事件驱动编程（Event-Driven）**
- **核心思想**：基于事件监听与**事件循环（Event Loop）**，被动接收外部信号并触发回调。
- **主流载体**：Node.js、浏览器 DOM 事件处理、消息队列（Kafka/RabbitMQ）。
- **工程场景**：前端交互、高并发网络服务、异步任务解耦。

```ts
// 不主动轮询，等事件来敲门
button.addEventListener('click', () => console.log('被点了'))
```

**3. 响应式编程（Reactive）**
- **核心思想**：基于**数据流与变更传播**，数据一变，依赖它的地方自动同步联动。
- **主流载体**：Vue 响应式系统（ref/reactive）、RxJS。
- **工程场景**：前端 UI 与数据状态自动绑定、复杂异步数据流合成。

```ts
const price = ref(10)
const count = ref(2)
const total = computed(() => price.value * count.value) // price 一变，total 自动重算
```

> 区别：**事件驱动**是"事件来了通知你"，**响应式**是"数据变了自动帮你算/渲染"。

## 三.解耦与扩展类（架构怎么设计、类型怎么安全）

这一类决定了如何剥离公共逻辑、降低模块耦合度，并提高代码复用性。

**1. 泛型编程（Generic Programming）**
- **核心思想**：**类型参数化**，用统一的代码结构安全地处理不同类型的数据。
- **主流载体**：TypeScript（`<T>`）、Java（`<T>`）、C++（STL）。
- **工程场景**：公共组件封装、通用 API 请求库、工具函数库。

```ts
// 一份代码，类型还能被推断出来
function wrap<T>(value: T): { data: T } {
  return { data: value }
}
const r = wrap(123)   // r.data 的类型自动是 number
```

**2. 面向切面编程（AOP）**
- **核心思想**：**横向插入**公共逻辑，把日志、权限、事务等从核心业务中剥离。
- **主流载体**：TypeScript 装饰器（@Decorator）、Python 装饰器（@decorator）、Spring AOP。
- **工程场景**：接口日志打印、用户 Auth 权限校验、数据库事务控制。

```ts
function Log(target: any, key: string, desc: PropertyDescriptor) {
  const origin = desc.value
  desc.value = function (...args: any[]) {   // 业务代码没动，外面套了一层
    console.log(`调用 ${key}`, args)
    return origin.apply(this, args)
  }
}
```

**3. 控制反转与依赖注入（IoC / DI）**
- **核心思想**：把对象的**创建与依赖管理交给外部容器**，实现模块间解耦。
- **主流载体**：NestJS、Java Spring 框架、Angular。
- **工程场景**：大型企业级后台系统的服务层与依赖解耦管理。

```ts
// 自己 new 依赖 → 耦合死；改成"从构造函数要" → 容器送进来
class UserService {
  constructor(private readonly repo: UserRepository) {}  // 依赖由外部注入
}
```

> **控制反转**是思想（控制权从"我"变成"容器"），**依赖注入**是它的具体实现手段。

## 四.速查表

| 范式 | 一句话核心 | 典型载体 |
| ---- | ---- | ---- |
| OOP | 数据 + 行为打包成对象 | Java、class |
| FP | 纯函数、不可变、管道化 | map/filter/reduce、Stream |
| POP | 按步骤写函数和控制流 | C、Shell |
| 声明式 | 只要结果，不管过程 | SQL、HTML、模板 |
| 事件驱动 | 事件来敲门，回调响应 | Node.js、DOM、MQ |
| 响应式 | 数据变，依赖自动联动 | Vue、RxJS |
| 泛型 | 类型参数化，通用又安全 | `<T>`、STL |
| AOP | 横向插入公共逻辑 | 装饰器、Spring AOP |
| IoC / DI | 依赖交给容器管 | NestJS、Spring |

---

## 五.怎么选（实战判断）

- **建系统骨架** → OOP 打底（类 = 领域模型），天然合适。
- **搬数据、做转换** → FP 上，链式调用比一堆 for 循环清爽得多。
- **写运维/批处理脚本** → POP + Shell，别过度设计。
- **UI 联动** → 声明式 + 响应式，让框架帮你算。
- **重复的日志/权限/事务** → AOP 抽出来，别在每个接口里抄一遍。
- **大项目的依赖管理** → IoC/DI，避免模块间互相 new 成死结。

**核心一句话**：范式不是用来背的，是**看场景挑工具**——语言是壳，思维模型才是内核。
