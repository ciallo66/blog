# 一些小知识点

### 1.RESTful API
RESTful API 是一种特殊风格的接口，主要特点有如下几个：
- URL 中的路径表示资源，路径中不能有动词，例如 `create`，`delete`，`update` 等这些都不能有
- 操作资源要与 HTTP 请求方法对应
- 操作结果要与 HTTP 响应状态码对应

规则示例：

| 操作 | 请求类型 | URL | 返回 |
| ---- | ---- | ---- | ---- |
| 新增歌曲 | POST | /song | 返回新生成的歌曲信息 |
| 删除歌曲 | DELETE | /song/10 | 返回一个空文档 |
| 修改歌曲 | PUT | /song/10 | 返回更新后的歌曲信息 |
| 修改歌曲 | PATCH | /song/10 | 返回更新后的歌曲信息 |
| 获取所有歌曲 | GET | /song | 返回歌曲列表数组 |
| 获取单个歌曲 | GET | /song/10 | 返回单个歌曲信息 |

### 2.res.json()作用
```js
// Express 底层简化的伪代码（它帮你写的）
res.json = function (obj) {
  let val = obj;

  // 1. 核心关键点：在后台悄悄咪咪调用 JSON.stringify()，把你的对象转成纯文本字符串！
  let body = JSON.stringify(val);

  // 2. 告诉浏览器：“哥们，我给你发的是标准的 JSON 文本，你准备好接货！”
  // （这就免去了你手动写头信息的痛苦）
  this.set('Content-Type', 'application/json');

  // 3. 啪的一声，把这串纯文本字符串通过网络真正发送给前端
  return this.send(body);
};
```

### 5.Swap(虚拟内存)
**介绍**：当你的物理内存（RAM）不够用时，系统就会把内存里暂时不用的数据挪到硬盘swap  
**优点**：当内存挤爆时，它可以当防爆盾，防止系统直接崩溃或强杀你的进程（比如 MySQL）。  
**缺点**：硬盘的读写速度比物理内存慢几百倍。一旦系统频繁调用 Swap 里的数据，服务器就会明显变卡。  

#### 初始化
```js
//1.创建一个2GB 的 Swap
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile

//2.让 Swap 分区永久生效
echo "/swapfile swap swap defaults 0 0" | sudo tee -a /etc/fstab && 

//3.永久修改 Swap 的使用比例（改为 30），并让它立刻生效(比例越大swap占用越大)
echo "vm.swappiness=30" | sudo tee -a /etc/sysctl.conf && sudo sysctl -p
```

### 6.浏览器的缓存
#### 1.前端数据存储（存数据）

| 位置 | 大小 | 生命周期 | 特点 | 常放什么 |
| ---- | ---- | ---- | ---- | ---- |
| Cookie | ~4KB | 有过期时间 | 每次请求自动携带；服务端可写；可 httpOnly 让 JS 读不到 | sessionId、**refresh token（httpOnly）** |
| localStorage | ~5MB | 永久 | 只能存字符串；不随请求发送 | token（**不推荐**，XSS 风险）、主题、草稿 |
| sessionStorage | ~5MB | 关标签就没 | 同 localStorage，但不跨标签共享 | 临时状态、access token（妥协） |
| IndexedDB | GB 级 | 永久 | NoSQL 数据库；能存对象/二进制 | 大数据、离线数据 |

#### 2.HTTP 资源缓存（存文件）

常说"js缓存""浏览器强缓存"就在这——**js缓存不是单独一种**，就是 js 文件被下面的缓存命中了。

| | 强缓存 | 协商缓存 |
| ---- | ---- | ---- |
| 发请求吗 | 命中后**一个请求都不发**，直接用本地 | 发一次问"变没变"，没变返回 **304** |
| 控制头 | `Cache-Control`、`Expires` | `ETag`、`Last-Modified` |
| 命中表现 | `200`（from memory/disk cache） | `304 Not Modified` |

> 优先级：Cache-Control > Expires；ETag 比 Last-Modified 精确。物理分两层：memory cache（内存）/ disk cache（磁盘）。命中显示：Network → Size 列 `from memory cache` / `from disk cache` / `304`。

#### 3.Service Worker 可编程缓存（做离线）

JS 自己写代码控制缓存哪些请求/响应，命中优先级最高，一般做 PWA 离线。

> 查找顺序（快→慢）：**Service Worker → Memory → Disk → Push Cache → 网络请求**。
>
> 双 token：refresh（长）→ httpOnly Cookie；access（短）→ 内存 / sessionStorage。别放 localStorage。
